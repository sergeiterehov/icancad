# ADR 0013 — Operation editing, rebuild snapshots and phantom preview

Status: accepted (M2)

## Context

Operations reference geometry that existed before them: a sketch is attached to a body face, an extrude picks sketch faces and body faces, a delete removes a body. Until now any operation could be edited with the timeline wherever it was, so the references were resolved against a model that had already been changed by the operation itself and by later operations. Changing the timeline position after an edit also rebuilt the whole history from scratch, which made "just look at an operation" as expensive as a real edit.

ADR 0002 already established that an edit belongs to its own timeline position and locks the timeline until editing ends. This ADR applies the same rule to every operation — a sketch included — and makes moving between operations cheap.

## Operation model

An operation is a function of one input — the model state before it — with two outputs:

1. the **result delta**, the change the operation makes to the model; and
2. a **non-modifying delta**, a phantom preview of that change.

The preview is merged over the input state for display only. Interaction in the 3D view (hover, picking, body-face references) always runs against the input state: the hit map is the input model while the picture shows the input plus the phantom delta. This keeps every reference an operation makes valid by construction, because neither the operation itself nor any later operation has modified the geometry it points at.

## Decisions

| Area                     | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Entering an operation    | Selecting any operation shows the state in front of it, so the model is exactly its input. This includes a sketch, in the sketch editor as well: the sketch itself is drawn from its preview.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| The cursor while editing | The document cursor never moves for an operation edit: it is the user's position, so it stays where the user left it, is what autosave stores and what the project exports. The input position is derived instead — `projectForView` returns the document with the cursor placed in front of the edited operation — and everything that draws or reports the model reads that view. The timeline caret therefore stays at the user's position and no caret is added after the edited operation; the selected operation itself marks where the model is being evaluated.                                                                                                                                                                                                                                                                                                                                                                  |
| Leaving an operation     | Dismissing the operation (clicking empty space, selecting another object or operation, deleting it) only drops the view override, so the model returns to the user's cursor — which is exactly where it was before the operation was opened. Moving a caret or creating an object also ends editing. The timeline carets are disabled while an operation is being edited, including while a sketch is open.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Rebuild snapshots        | The rebuild pipeline stores the state after every operation: body shape ids, tessellation, per-body topology counts, sketch frames and per-operation errors. A snapshot is reusable while the identity of every feature in its prefix is unchanged. Features are immutable, and an edit replaces the feature object, so the snapshot of the edited operation and of every later one is dropped automatically.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Snapshot reuse           | A rebuild starts from the newest reusable snapshot at or before the cursor, normally making a cursor move a pure publish with no kernel work. Snapshots are kept past the cursor so moving forward again reuses them too.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Kernel shapes            | Shapes referenced by a snapshot stay in the worker; only shapes no snapshot references are disposed, so a snapshot can always be continued.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Preview                  | The edited operation is evaluated on top of the cursor state and published with the scene. This is the only operation that runs while it is being configured; later operations stay rolled back. Opening an operation that was already evaluated reuses its snapshot instead of recalculating it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Phantom delta            | The preview is shown as a phantom instead of silently changing the model. The tree marks added objects green with a plus icon (dimmed, not selectable), changed objects yellow with a pen icon, and removed objects red with a minus icon (still selectable). In the 3D view added and union results are translucent in their body colour, a removed body stays visible in red, and a cut keeps the resulting solid so the hole reads as a hole while the removed volume is shown as a translucent red ghost. A cut through the whole model keeps its ghost as red as a blind cut up to the point where it leaves the material and only then fades out, so a through cut does not end in a hard red block. The fade covers 100 screen pixels, capped to the length the ghost still has past the exit: the ghost is only slightly longer than the model, so an uncapped fade would be cut off mid-gradient and read as a hard edge again. |
| Hit map                  | Picking keeps the tessellation of the input model for every body, including the ones the preview changed or removed. A cut therefore still hits the material that the phantom shows as removed, and a body face picked while editing returns the face ids of the input shape. Objects the operation adds are not part of the input, so they are drawn but cannot be picked.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Change detection         | A boolean against a body the tool misses still produces a new shape; the tessellation signature decides whether a body is really marked as changed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Through-all reach        | A through cut has to clear the whole model along its direction. The reach is measured on the tessellation vertices, not on the bounding-box corners: along an oblique direction the farthest point of a body is a mixed corner that the axis-aligned box does not contain, which used to leave a thin wall at the far side of the cut.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Hidden sketches          | A hidden sketch is shown while its operation is selected or its editor is open, because it cannot be configured unseen. This is a view override like the cursor: the stored visibility is untouched, so the sketch is hidden again as soon as the operation is dismissed, and the eye in the tree keeps reporting the stored state.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Face provenance          | Every rebuild records which operation created each face of each body. A boolean keeps the faces it does not touch, so the kernel reports, per face of the result, the face of the input it came from, and the rebuild continues that chain. A double click on a face in the 3D view opens that operation: an untouched face still leads to the operation that first created the body, and only the faces an operation created or rebuilt lead to that operation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | A body is rarely the work of one operation, and the operation that made a face is the one whose parameters explain it. |
| Manual rebuild           | The operation context menu offers "Rebuild from here", which drops every snapshot from that operation on and recalculates the model. It is the escape hatch for a stale cache.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

## Consequences

- Configuring an operation always sees valid references, because later operations and the operation itself cannot have modified the geometry it points at; the preview can never change what the user picks.
- The sketch editor is not a special case any more: it edits the sketch operation exactly like the inspector edits an extrude, with the sketch drawn from the preview.
- Moving between operations and opening their settings is instant for an already computed model; a real parameter change recalculates only that operation and, after editing ends, the operations after it.
- Memory grows with the number of operations, but snapshots share tessellations, so the extra cost is one set of maps and arrays per operation.
- Because editing never writes the cursor, reloading the page while an operation is open lands on the position the user had before entering it, not on the operation.
- The preview is transient: it is never written to the document. Bodies created by a previewed operation get their `bodyId` refs only when the operation is committed, and their names and colours then match what the preview showed.
- Undo/redo and project import replace feature objects, so their snapshots are dropped; this is correct although it loses the reuse for those actions.
