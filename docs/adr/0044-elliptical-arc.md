# ADR 0044 — Elliptical arc

Status: accepted

## Context

The sketch had circles, circular arcs and full ellipses, but no arc of an ellipse. That is the missing primitive for slots, cams, and any profile that continues an ellipse between two angles. The tool rail could not show one more button without becoming a wall of icons, so the arc button grew a chevron in ADR 0043.

## Decisions

| Area                     | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Entity                   | `elliptical-arc` carries a centre, both semi-axes, the rotation of the local X axis in degrees, and the start and end angles in that frame in radians. Angles follow `arc`, rotation follows `ellipse`, so the two existing conventions are reused rather than replaced.                                                                                                                                                                            |
| Control points           | Centre, the end of the first semi-axis, the end of the second semi-axis, and the two ends. The first two handles resize and turn the ellipse; the ends only move their angle along it.                                                                                                                                                                                                                                                              |
| Focus                    | The focus of an `ellipse` primitive sits on the longer axis a quarter turn on when Y is the longer one. The offset is computed from the turn in degrees, so a turned ellipse reaches the solver as the curve the sketch shows; reading degrees as radians moved the focus, and every solve then turned and reshaped the ellipse.                                                                                                                    |
| Solver representation    | An elliptical arc is an `ellipse` primitive for the centre and the two axis handles, plus an `arc_of_ellipse` primitive that shares that centre, focus and minor radius and owns both end angles. `arc_of_ellipse_rules` ties the two arc ends to those angles, so an end stays a real point that coincidence, fixation and dragging can move like any other point.                                                                                 |
| Round trip               | A solved ellipse and a solved elliptical arc read their centre, semi-axes and rotation back from the axis handles and, for the arc, both angles from the arc primitive. The handles keep the authored frame, so an ellipse whose Y axis is longer than its X axis does not flip its angles after a solve, and the authored clockwise direction survives a solve.                                                                                    |
| Snapping and constraints | A point snapped to the arc becomes `point-on-ellipse`, like a full ellipse. Radius, diameter and tangency are not offered for an elliptical arc: the ends are the points a user constrains, and the ellipse has two radii. The included angle is offered and is driven by a `difference` between the two arc angle parameters. A driving arc length is not offered, see Consequences.                                                               |
| Profiles                 | An ellipse and an elliptical arc reach the kernel as exact `gp_Elips` edges, so their extrusion gets one smooth side instead of a facet per polyline segment, the way a circle does; the contour still keeps the entity key, so an extrude side keeps its name. Profiles, topology and regions sample the same curve the view draws.                                                                                                                |
| Tool                     | Five clicks: centre, the end of the major half-axis (length and rotation), the end of the minor half-axis (its perpendicular extent), the start angle, then the end angle. After the first two clicks the whole ellipse is previewed, so both axes can be judged before the arc is cut out of it. The start and end steps snap to nothing: their click only names an angle on the ellipse, and a magnet target there could not become a constraint. |
| Icon                     | Lucide has no elliptical arc, so the rail and the inspector use a locally drawn arc between two end dots.                                                                                                                                                                                                                                                                                                                                           |

## Consequences

- An elliptical arc is an open curve everywhere: profile loops close through its ends, topology registers its centre and ends, and the array path does not treat it as closed.
- `point-on-ellipse` is the only curve constraint it accepts; a fully constrained arc is built from coincidences, distances and fixes on its points.
- Arc length stays a driven reference measure. planegcs only derives `arc_length` from a circular `Arc`, and rejects an `arc_of_ellipse` with a binding error, so a driving length for an elliptical arc would need an elliptic integral the solver does not have. The inspector therefore measures the length but does not offer it as a constraint.
- The entity type list is a discriminated union, so a missing switch case fails type checking rather than silently rendering nothing.
