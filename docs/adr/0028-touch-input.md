# ADR 0028 — A finger gets the same tools as a pointer

Status: accepted

## Context

The app ran on a tablet with half of itself missing. Panels opened and kept their
state, but slid away again a second later, because auto-hide waits for a pointer
that hovers and a finger cannot. A bubble popped up over every button that carried
a tooltip, because a tap arrives as a hover followed by a focus. No context menu
could be opened at all: a finger has no right button, and the platform that runs
the tablet never sends `contextmenu` for a long press. The 3D view ignored fingers
while the nav cube turned under the same finger, since the camera asked a media
query whether the device had a coarse pointer and believed the answer instead of
the event. The sketch took taps, so a line was a chain of taps — the one gesture a
finger does not have to be taught.

## Decisions

| Area              | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| What a finger is  | The event says so: `pointerType === 'touch'` (`isTouchPointer` in `viewport/inputProfile.ts`). No media query takes part: a hybrid device reports whichever pointer was used first, and the event is never wrong.                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Context menu      | A finger that rests for 520 ms without travelling more than 12 px asks for the menu of what is under it. The press is turned into a `contextmenu` event at that point (`ui/longPress.ts`), so every menu in the app keeps its one definition and becomes reachable.                                                                                                                                                                                                                                                                                                                                                                                          |
| Long press        | The gesture is installed once, by the host that draws menus. Inputs and editable text keep the long press of the platform, which selects text rather than opening a menu. The tap that follows a menu is swallowed, so it does not also press the control.                                                                                                                                                                                                                                                                                                                                                                                                   |
| Tooltips          | A tooltip belongs to a pointer that can rest on a control: a mouse or a pen. A finger never opens one. A focus that came from a tap is not keyboard focus either, so focus shows a tooltip only while `:focus-visible` matches.                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Panels            | A panel is worked by the hand that is on it, and the two hands are two behaviours. A cursor opens a panel by coming to its edge or its tongue and gives it back by leaving, so a panel under a mouse lives as long as the mouse is over it; the inspector of a selected operation holds it open, because a form is read rather than passed by, and so does a menu opened from inside the panel. A finger can neither hover nor leave, so for it a panel is opened on purpose — the screen edge, the tongue, or the operation that needs it — and then stays open until the tongue says otherwise. The two are one table of decisions in `ui/dockGesture.ts`. |
| Start-up tuck     | The one move a panel makes on its own happens at launch: it is open so the workspace shows what it has, and a second later it slides away, so the model keeps the screen. That is the same slide the tab gives it, on every device. The clock starts after the open panel has been painted, because on a slow machine the kernel and the shaders keep the main thread busy, and a collapse set before the first frame would have nothing to animate from. A hand on the panel cancels the timer, and after it nothing closes a panel but the tab.                                                                                                            |
| Closing           | A finger closes a panel with the tongue, and only with it: the tongue is on screen whenever the panel is, and its arrow turns inwards while the panel is open. A cursor needs no such way out — it makes that move by leaving, so a tongue on an open panel would be a control for something the cursor does anyway — which is why the tongue is drawn on a folded panel alone and the panel goes when the pointer leaves.                                                                                                                                                                                                                                   |
| Pinning           | The inspector has a subject: the operation on screen. While there is one, the panel shows the state that subject asks for — unfolded by default — and it rules over the panel's own state. Pressing the tab while a subject is there folds the subject's state away, not the panel's; the panel's own state is untouched meanwhile and comes back exactly as the user left it once the subject is gone. A different subject arrives unfolded. The object tree is a map of the model rather than a form, so nothing unfolds it but the user.                                                                                                                  |
| Pin preference    | The "Закрепить" switch in the project menu is gone: with nothing to auto-hide there is nothing to hold, and the switch had no other meaning.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Nested menu       | A tap opens a submenu and the submenu stays. A finger's tap sends a hover before its click, so hover opens a nested menu only for a pointer that can hover; for a finger the click decides, which is also what closes it again on a second tap.                                                                                                                                                                                                                                                                                                                                                                                                              |
| Menu size         | A menu never leaves the window. It is placed inside the edges, and it keeps a ceiling at the window height and scrolls what does not fit. A nested menu is drawn fixed, so the menu it belongs to can scroll without clipping it, and it follows its row while that menu scrolls. Both placements are pure functions in `ui/menuPlacement.ts`.                                                                                                                                                                                                                                                                                                               |
| Selection         | A pointer with no keyboard to hold a key with — a finger or a pen — clicks additively: a list toggles the row it lands on, and the 3D view and the sketch canvas add the element picked. A click carries no pointer type of its own, so the press before it decides (`installPointerWatch`). Empty space always clears, whatever the pointer: there is no row out there to toggle.                                                                                                                                                                                                                                                                           |
| Operations        | The strip of operations reads a finger differently, and says so itself (`finger: 'replace'` in `ui/useListSelection.ts`): a tap takes the operation on its own. An operation is the one thing being edited — its parameters own the inspector and the model is evaluated at its place — so there is nothing to add it to. The modifiers still work there for a keyboard.                                                                                                                                                                                                                                                                                     |
| Hover-only rows   | A row action follows the hand in use. A cursor reveals it by resting on the row, so a list stays tidy for a mouse; a finger cannot hover, so on a touch screen the eye of an object and the remove action of a selected row are on screen all the time. The stylesheet reads the hand from the document, which `installPointerWatch` keeps current from the pointer that presses, starting from what the platform reports.                                                                                                                                                                                                                                   |
| Corner gives way  | The strip of tools and the project mark share the top row, and the mark never gives way: the strip keeps the row and the corner steps back in order — first the project name and the rule before it, then the product name, and only with the mark alone beside it does the strip start to shrink. A tablet is too narrow for both, and losing the project name is cheaper than losing the tools.                                                                                                                                                                                                                                                            |
| Placement row     | The plane tabs of a sketch keep their labels. Safari shrinks a nested flex row far earlier than Chrome does and ellipsised every tab while the number field kept its full width, which read as a broken row on a tablet; now no tab falls below the width of its own label and the number gives way instead.                                                                                                                                                                                                                                                                                                                                                 |
| Tab size          | A panel that is away gives its tab a taller and wider hit area than the thin tongue it draws: a fingertip covers more than a cursor does.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Camera            | Touch follows the pointer type of the event, not the input profile. One finger orbits the point it holds, two fingers pan and pinch, and a tap still selects. The sketch editor owns one finger while it is open; two fingers stay the camera's, because a sketch that cannot be zoomed is unusable on a tablet.                                                                                                                                                                                                                                                                                                                                             |
| Handles           | A finger that comes down on a handle of a quick operation pulls it: a tablet has no second button to offer, and the arrow is exactly what the finger aims at. Every other finger turns the view, and a second finger takes the gesture away from a handle, so a pinch is never fought over.                                                                                                                                                                                                                                                                                                                                                                  |
| Sketch pick       | In a sketch a keyless press is read where it happens, on the press itself: the first one takes the entity on its own, the next ones add it, and the click the browser sends afterwards is dropped so the same tap is never read twice. A tap never drags either: geometry starts moving only after the same slop that tells a tap from a stretch, so a finger or a pen that lands on a line selects it instead of nudging it.                                                                                                                                                                                                                                |
| Sketch creation   | A tap keeps its old meaning: it places the point the next click would have placed. A finger or a pen that travels instead stretches the primitive between the point it came down on and the point it lifts on. Both ends run through the same picker, so a magnet, a snap and the grid cannot disagree between a tap and a stretch.                                                                                                                                                                                                                                                                                                                          |
| Point             | The press point is not used: the point follows the finger and is placed where it lifts.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Line              | The stretch is one segment from the press to the release, and it finishes the chain — the next line starts from scratch. A press and release in one spot still adds the next vertex of a chain.                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Circle            | The press is the centre, the release is a point on the circumference.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Ellipse           | The press is the centre, the release gives both half axes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Arc               | The stretch supplies what a stretch can name: the press is the centre, the release is the start point, and the end angle waits for the next tap or stretch.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Bézier            | The stretch appends the release point to the curve and finishes it, so a curve can be drawn with taps and closed with one pull.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| A mouse           | Keeps the click flow. It is precise enough to place two points, and a drag with it already means a selection box or a view swing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Thresholds        | One slop, `TAP_SLOP_PX` in `sketch/createGesture.ts`, 8 px, decides both what counts as a stretch and what counts as a tap, so a gesture can never be read as neither.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Echo of a stretch | The browser still sends a click after a finger lifts. That click is dropped: the stretch already placed its points.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Cancelled gesture | A pointer the platform takes away drops the stretch instead of committing it where it happens to be.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

## Consequences

- Touch behaviour is decided where the gesture happens, so nothing has to be
  switched on: the same build works with a finger, a pen and a mouse, and a
  hybrid laptop switches between them without a setting.
- Menus are written once. A new `onContextMenu` handler is reachable by a finger
  without knowing that long press exists.
- The gesture rules are pure modules (`ui/longPress.ts`,
  `sketch/createGesture.ts`) with no DOM, so they are covered by unit tests while
  the components stay as they are.
- A tablet can now compose a sketch with the gesture it has: a line, a circle and
  an ellipse are one pull each, and a point follows the finger that places it.
- Limits: the arc still needs a second gesture for its end angle, because one
  stretch cannot name three points. A finger resting on a control for half a
  second opens its menu, which a very slow tap can do by accident.
