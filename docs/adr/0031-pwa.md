# ADR 0031 — The app installs, and works without a network

Status: accepted

## Context

The document already lives in the browser: projects are saved to IndexedDB and `.icad` files are local. What still needs a server is the application itself — its code and the 63 MB OCCT binary. So a user who loses a connection, or opens an installed icon, gets a tab that cannot reload, even though their work is safe on disk.

The parts of the app are very different in size and in how often they change. The shell (entry chunk, CSS, three workers, the planegcs WASM, icons) is about 2.5 MB and changes with every build. OCCT is 63 MB and changes when the kernel dependency does, which is rare. A modeler also keeps a tab open for hours, so a deployment often happens under a session that is still running — and the reload an update requires must not cost the user the last edit sitting in the autosave debounce.

## Decisions

- **The PWA layer is web-only and generated.** `vite-plugin-pwa` with the `generateSW` strategy emits `manifest.webmanifest`, the service worker and its Workbox runtime from [apps/web/vite.config.ts](../../apps/web/vite.config.ts). Nothing in `packages/model`, `packages/kernel` or `packages/io` knows that a worker exists.

- **The shell is precached; the kernel is not.** Precaching is the install: the app shell and the sketch solver have to be there on the first offline start. OCCT is left out — installing would otherwise cost 63 MB before the app is usable — and is cached when the kernel first asks for it.

- **The first visit waits for the worker.** Precache finishes during install, but the page that started the install is not controlled by the worker until it activates, and a kernel download started before that would bypass the cache — leaving the app online-only until a second visit. The worker claims its clients on activation (an update still waits for the user), and the kernel boot waits for that claim, three seconds at most.

- **The OCCT URL carries a content hash.** The public file keeps its name, so the cache-first response would otherwise hide a new kernel behind a stale cache entry forever. `vite.config.ts` hashes the binary at build time and defines `__OCCT_WASM_REVISION__`; the kernel worker appends it as `?v=…`. The cache can then keep the response without checking the network: an unchanged binary is never downloaded twice, and a changed one is a different URL, so the old entry is evicted by `ExpirationPlugin`.

- **An update waits for the user.** A new worker does not take over under a running session; it waits, and the app offers *Reload*. Before activating it, `applyUpdate` flushes the open project, so the reload cannot outrun the autosave. The page also asks for a new deployment hourly because a tab can outlive many deploys.

- **Install is an offer, not a prompt.** `beforeinstallprompt` is kept from the moment the browser fires it and is used only when the user picks *Install app* in the project menu. iOS has no such event; the menu item shows *Share → Add to Home Screen* instead, and the document carries the iOS meta tags. The manifest icon paths stay relative so a project site under `/icancad/` installs from the same build as a domain root.

- **The browser chrome follows the theme.** The `theme-color` meta tag is repainted with the app theme, so an installed window does not keep a dark title bar over a light workspace.

## Consequences

- The PWA needs HTTPS (or localhost) for the worker; GitHub Pages and `vite preview` provide that. The manifest and worker inherit `VITE_BASE`, so the Pages build installs with the same scope it is served from.
- The first kernel start still needs a network; every later start, offline or not, is served from the cache. The cache holds one OCCT revision, about 63 MB.
- Vite serves modules uncached in development and the worker is registered only for a production build, so PWA behaviour is verified with `build` + `preview` (see [README.md](../../README.md#progressive-web-app)).
- The web app gains Workbox as a build dependency; the bundle grows by the registration client (about 6 kB).
